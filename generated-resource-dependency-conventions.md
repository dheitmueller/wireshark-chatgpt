# Wireshark Generated-Resource Dependency Conventions

This file records durable build-system conventions for generated resources and their inputs. Current upstream CMake files remain authoritative.

## Generated resource manifests need explicit dependencies on generated inputs

A generated resource manifest is not sufficient to order the generation of files it names. If a `.qrc` or similar resource description references outputs such as generated translation files, the build graph must explicitly ensure those outputs exist before the resource-generation step consumes them. Relying on an incidental target order leaves a silent race that can surface only under different generators or timing.

In merged master MR !24425, review identified a latent race in `ui/qt/CMakeLists.txt`: translation `.qm` files were added to an autogenerated QRC before the files were guaranteed to have been generated. The discussion noted that the CMake file itself already contained an intent to enforce this ordering, but the dependency had not actually been implemented; reworking QRC generation made the latent race observable.

**Implementation rule:** whenever a generated file is consumed by another generated resource, represent producer-before-consumer ordering in the CMake dependency graph. Do not rely on configure-time file presence, source-list order, or a neighboring comment that describes the intended ordering without creating it.

**Confidence:** High. The race was identified and resolved in review of a merged master build-system MR; the general dependency-graph rule is independent of the specific QRC helper implementation.
