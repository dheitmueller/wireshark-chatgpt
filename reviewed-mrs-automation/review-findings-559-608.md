# Review findings: Wireshark MRs !559-!608

## High-value findings

- **!579 and !580 — Wiretap error contracts.** Guy Harris extends Wiretap writer APIs so a coarse numeric error such as `WTAP_ERR_INTERNAL` can carry an owned `err_info` string describing the violated invariant or concrete failure. Open/close paths initialize the detail channel, format-specific writers populate it, callers propagate/display it, and consumers free it. !580 improves the final write-error presentation. This is strong API and ownership precedent.
- **!564 with closed !562 — tree-independent semantic dissection.** !564 removes a broad `if (tree)` guard from CLASSIC-STUN so first-pass transaction and attribute processing still occurs when no protocol tree is being rendered. In !562, Pascal Quantin caught that moving the core null-tree early return ahead of field-length checks would suppress validation/exceptions on the first pass; Anders Broman agreed and the proposal closed. Tree availability is presentation state, not permission to skip semantic parsing or validation.
- **!571 — QUIC heuristic bounds.** Peter Wu explains the short-header structural minimum and why the heuristic needs at least one CID byte even though an empty CID is legal QUIC. The merged fix caps the copied CID by captured bytes remaining after mandatory framing instead of unconditionally reading the maximum CID width. Heuristic recognition should be bounded by both the packet and the actual identity evidence the lookup requires.
- **!601 — shared field rendering.** Gerald Combs adds a libwireshark display-label helper and moves the Qt packet diagram onto that shared formatting path instead of reconstructing field presentation in the UI. He validated varied custom-column field types and checked that tshark output remained identical.
- **Closed !585 — string/display semantics.** Guy Harris gives authoritative negative guidance: for `FT_STRINGZ`, `FT_STRINGZPAD`, and `FT_STRINGZTRUNC`, padding and the terminator are not part of the semantic string value. `proto_tree_add_item_ret_display_string()` is intended to return user-facing display text, and fetch-once/add-once followed by updating a parent summary is preferable to prefetching bytes separately. The proposed export did not merge, so only the review guidance is retained.
- **!565 and !566 — time fields.** Two merged cleanups replace manual integer extraction into `nstime_t` with `proto_tree_add_item()` plus `ENC_TIME_SECS` or `ENC_TIME_SECS_NSECS` and the proper byte order. When the wire layout already matches a registered time encoding, the generic field API should own the conversion.
- **!606 — generated ASN.1 semantic constraints.** Pascal Quantin points out that the generic ASN.1 `OCTET STRING` type does not itself guarantee the protocol-specific eight-byte gmIdentity extent. The accepted custom generated-code path validates the semantic length before fixed-width EUI-64 access. Generator schema breadth does not remove protocol-specific validation obligations.
- **!589 with closed !585 — ABI symbol versioning.** Pascal Quantin corrects the Debian symbol version to 3.3.2 because 3.3.1 was already released. This corroborates the existing notebook rule that symbol manifests record the first shipped release containing an API, not an approximate development version.
- **!582 — capacity changes need resource analysis.** Ronnie Sahlberg asks for memory-impact analysis before raising `COL_MAX_LEN` eightfold because allocations depend on that constant. The contributor reports testing a capture above 500,000 frames with no visible memory change. Pascal Quantin also questions stable-branch backporting of this behavior change, treating it as the sort of change normally reserved for the next major release.
- **!605 / closed !604 and !594 — submission hygiene.** Pascal Quantin directs the contributor to amend an existing MR rather than open a replacement for the same change and requires the maintainer-edit permission needed for rebases/minor edits. Dario Lombardo rejects duplicated commits, an accidental merge commit, and submitting a patch file instead of the patched source. These strongly corroborate existing submission conventions.
- **!593 — remaining-length accounting.** The EPL fix keeps explicit remaining segment size rather than repeatedly deriving the last-entry extent from unrelated offsets, and guards data length against the bytes remaining before consuming it. Useful corroboration for authoritative remaining-capacity accounting.
- **!560 — reassembly object identity.** John Thacker fixes a NULL check to test the current fragment's `tvb_data` rather than the aggregate head's pointer before dereference. The change is deliberately narrow; he notes a separate MR contains broader cleanup. This is a useful example of fixing the object whose invariant actually guards the imminent access without pretending the narrow safety fix resolves every related diagnostic issue.

## Lower-information or corroborating work

The remaining merged MRs were reviewed for diff/discussion content but did not justify new notebook rules. These include UI styling/tooltip work, STUN/PFCP/WSP protocol-local changes, CI/build maintenance, documentation cleanup, release backports, and small correctness fixes. Closed drafts/superseded submissions were counted but not treated as accepted implementation architecture.
