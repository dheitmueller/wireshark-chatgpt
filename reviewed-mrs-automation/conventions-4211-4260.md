# Durable conventions from MRs 4211–4260

Corpus commit: `ddcaa22b51c68f594e425a23388c3a2086813054`

## Build and configuration

- **Reproduce optional-feature failures from clean CMake state before patching source guards.** In !4227 and !4223, Guy Harris traced `ENABLE_*` failures to stale or inconsistent cached discovery state and recommended clearing `CMakeCache.txt` or recreating the build directory. Merged !4221's SMI workaround was subsequently reverted by !4229. Inspect both `config.h` and `CMakeCache.txt` when `ENABLE_*`, `*_FOUND`, and `HAVE_*` disagree.
- **Do not derive package-manager prefixes from CPU architecture.** Closed !4242 contains high-authority review from Guy Harris, Gerald Combs, and Roland Knall: ask Homebrew for its own prefix with `brew --prefix`, and permit an explicit override where multiple installations or cross-target builds make `PATH` ambiguous. Because !4242 closed, this is reviewer guidance rather than accepted implementation precedent.
- **Distinguish target OS from toolchain.** Merged !4245 and !4246 show that `WIN32` does not imply MSVC; Visual Studio-only objects and checks need compiler/generator predicates so MinGW remains a first-class Windows target.
- **Keep generated configuration inclusion at translation-unit boundaries.** Merged !4247 moves `config.h` out of headers and into source files, avoiding macro-order and redefinition coupling across includers.

## Display filters and field metadata

- **Allow semantic context to reinterpret ambiguous identifiers.** Merged !4214 and generalized !4238 convert protocol-looking RHS tokens back to an unparsed form so the expected literal domain, not premature global-name resolution, decides whether the token means bytes, a string, or another admissible value. This is an early precursor to the later stronger !6631 type-inference rule.
- **Treat checker output as structural evidence, not protocol truth.** Merged !4252 expands `check_typed_item_calls.py` folder/path coverage and field-width modeling while fixing concrete mask issues; !4218 shows maintainers running `--consecutive` and discussing whether repeated fields are actually a problem. Current checker behavior remains authoritative, and warnings still require semantic review.
- **Old cosmetic field renames are not modern compatibility precedent.** !4228 and !4225 changed registered filter abbreviations during spelling or terminology cleanup. Later stronger notebook rules establish display-filter names as compatibility surfaces; do not generalize these 2021 merges into permission for cosmetic renames.

## Profiles, preferences, and UI state

- **Explicitly register profile-owned files that are loaded lazily.** Merged !4219 stores Import Hex Dump settings in per-profile JSON; review found profile copy/import/export would omit the file unless it was known before the dialog opened. Merged !4251 adds `profile_register_persconffile()` for this class of file.
- **Respect preference and private-header boundaries.** During merged !4250 Roland Knall explicitly rejected including `prefs-int.h` and required UI code to access the preference through the public preference state. Private `*-int.h` headers are not convenience APIs for callers outside their owner.
- **Generated translation files are not hand-edited feature code.** !4250 review required removal of manually added translations because those files are generated by Wireshark's translation process.

## Reassembly and state identity

- **Fix the complete uniqueness domain, not just the reproducer.** Closed !4256 is useful negative evidence from John Thacker: frame number can collide when multiple TCP multisegment PDUs begin in one frame, while sequence number alone can wrap or be reused across connections and relative numbering. The correct direction is flow-scoped identity plus a per-instance discriminator. Later merged !6330 and !6331 remain the stronger implementation precedent.
- **Do not weaken an invariant error just to suppress a symptom.** In !4256 John rejected simply returning from the "Frame already added in first pass" path; retransmission detection should normally make that impossible and the diagnostic remains useful while the true identity/layering problem is unresolved.
- **Teardown order follows callback ownership.** Closed !4236 was rejected because zeroing owned objects leaks them and deleting the main window earlier could leave later callbacks referencing destroyed UI state.

## Architecture and portability

- **Put generic formatting utilities in the lowest common library.** Merged !4212 moves generic numeric and IP conversion helpers and exported symbols from `epan` to `wsutil`, including symbol-manifest updates. This independently corroborates the later lower-layer ownership rule.
- **A project-owned compatibility implementation can be preferable to many platform-specific variants.** Merged !4213 adopts one musl-derived `getopt_long()` implementation everywhere; João Valverde's rationale, reviewed by Guy Harris and Gerald Combs, is consistent behavior across libc variants and elimination of MinGW-specific hacks.
- **Use the returned decoded field value for parser control flow when the same field is displayed.** Merged !4220 uses `proto_tree_add_item_ret_uint()` to drive optional-field presence, keeping tree rendering and control-flow interpretation on one decode.

## Submission and review practice

- **Amend the existing MR rather than discarding review history.** Roland Knall states this directly in merged !4250. The notebook already records the stronger modern form of this rule; !4250 is early corroboration.
- **Split unrelated infrastructure fixes out of feature MRs.** In merged !4253, Martin Mathieson and Stig Bjørlykke require TCP/reassembly changes to move to separate !4256 with their own description and test story.
- **Imported generated or protocol sources need provenance.** Anders Broman required the exact 3GPP document and version to be recorded alongside the ASN.1 in !4253.
- **Supply focused test material for protocol features.** The !4253 contributor provided a capture containing both X2 xIRI and X3 CC traffic plus the TLS key required to exercise it.
- **MR squash settings do not make a tangled topic history reviewable.** Anders still asked the !4253 contributor to clean the branch history before merge; the reviewable commit series matters before the merge button is pressed.
