## Durable findings promoted or strengthened in the notebook

### Use the reassembly API that matches native sequence semantics

Merged master !14004, authored and merged by John Thacker, replaces manual fragment-chain examination with `fragment_add_seq_offset()` because OPC UA fragments can start at a non-zero sequence value. The public offset-aware primitive is simpler and preserves more of the framework's normal ordering behavior. Added to `reassembly-conventions.md`.

### Keep Qt proxy/source column mappings structural and presentation ordering in the view

Merged master !13995, authored by John Thacker, fixes a shared-model sorting mismatch caused by a proxy that maps columns in source-relative order. The accepted change documents the constraint and points presentation-only reordering at `QHeaderView::swapSections()`. Added to `qt-model-conventions.md`.

### Cache order-sensitive analyzer results during the guaranteed forward pass

Merged master !13977, authored and merged by Gerald Combs, records that libsinsp requires events in chronological order and therefore caches extracted data on the first pass. Added to `single-pass-analysis-conventions.md`: stateful external analysis must not be re-driven by arbitrary redissection order.

### Preserve the root-cause capture error across cleanup

Merged master !13987 keeps the dumpcap-provided errno diagnostic instead of allowing the subsequent close-command path to overwrite it. Guy Harris directly approved the MR. Added to `capture-diagnostic-conventions.md`.

### Name API variants for their semantic extension, not their chronology

During merged !13975 review, Jaap Keuter explicitly rejected `*_new()` because temporal naming becomes stale and asked for a suffix describing what the API adds. The accepted `...with_description` form carries that semantic distinction. Added to `api-design-conventions.md`.

### Direct master evidence strengthens the plugin teardown rule

Merged master !13978, approved and merged by John Thacker, is the direct source for the rule already represented in `plugin-lifecycle-conventions.md`: plugin code cannot be unloaded while wmem teardown may still invoke plugin callbacks. The notebook now cites !13978 plus release-4.2 !13982, release-4.0 !13996, and the later release-3.6 backport !15684.
