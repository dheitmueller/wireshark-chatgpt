# Review findings 409-458

Corpus commit: `ddcaa22b51c68f594e425a23388c3a2086813054`

This batch contains 39 merged MRs and 11 closed/unmerged MRs. Merged implementation is weighted above closed or superseded proposals. Direct guidance from maintainers such as Guy Harris, Pascal Quantin, Peter Wu, Gerald Combs, Anders Broman, and Martin Mathieson is given correspondingly high weight.

## Strong findings

**!458 BSSAP field masks and value tables** — Vadim Yanitskiy fixed a value table whose entries used the pre-mask bit patterns even though Wireshark applies the registered `0xc0` mask before value lookup. The correct table therefore uses the post-mask values `0x02` and `0x03`, not `0x80` and `0xc0`. Anders Broman additionally suggested using `proto_tree_add_bitmask_list()` to express the grouped bitfield structure. Durable lesson: value tables attached to masked integer fields are indexed by the normalized value after masking/shifting; review masks and value tables as one contract.

**!456 / closed !450 / !443 Nettrace timestamps** — the accepted !456 solution separates immutable capture start time from each packet's derived timestamp and handles elapsed milliseconds with carry into seconds. Guy Harris also caught the accidental ancient `=-` operator, requiring `-=`. The rejected predecessors are useful negative evidence: copying historical behavior was not sufficient once Anders Broman compared the source against the 3GPP timing semantics and supplied a corrected approach.

**Closed !455 exported-PDU dissector identity** — Pascal Quantin rejected replacing a registered dissector name with a protocol short name merely because anonymous handles can return NULL. `EXP_PDU_TAG_PROTO_NAME` is used later to redispatch by registered dissector identity, and a protocol short name is not guaranteed to be that identity. The right fix is to preserve the registered-dissector contract, ensure dissectors that need name-based redispatch are actually registered by name, or introduce a different explicit dispatch criterion. The closed patch is not precedent; Pascal's contract analysis is durable.

**Closed !453 dark-mode profiles** — Stig Bjørlykke and Guy Harris both rejected coupling light/dark appearance to configuration profiles. Profiles carry protocol/workflow preferences and must remain orthogonal to system appearance; otherwise automatic theme changes unexpectedly switch much more than colors and users need duplicate profiles. Later merged theme work follows the runtime-palette direction instead. Treat this as negative architecture evidence, not accepted implementation.

**Closed !448 and merged !434 field-filter consolidation** — !448 attempted to reuse `wlan.fixed.action_code` for FST, but Alexis La Goutte noticed the value-string domain differed and the MR was closed. !434 made the analogous consolidation for Radio Measurement where semantics aligned and merged. Durable rule: sharing a display-filter field is valid only when the participating uses have the same semantic domain, width, and value mapping; superficial label similarity is insufficient.

**Closed !445 / !446 protocol/dissector-name compatibility** — Pascal Quantin rejected renaming NAS dissector registration names solely to make them look like field prefixes because tools and Lua can resolve dissectors by registered name. If a public identifier must change, retain compatibility through aliases where supported rather than silently breaking callers. These MRs were later superseded, so the proposed exact implementation is not precedent; the compatibility requirement is.

**!449 GTP field extraction** — Anders Broman changed a field that code both displays and consumes from a manual `tvb_get_ntohl()` plus separate tree insertion to `proto_tree_add_item_ret_uint()`. This keeps wire decoding, source range, field registration, and returned semantic value in one operation and avoids highlighting unrelated IE bytes.

**!439 Opus codec integration** — review by Pascal Quantin exposed an important packaging detail: the external library's Windows `opus.dll` collided with a Wireshark plugin of the same filename. The accepted change renamed the plugin to `opus_dec` and wired the optional dependency through CMake and packaging. Optional dependencies must be checked across runtime artifact namespaces, not only source-level symbol names.

**!438 Qt translations** — Gerald Combs replaced concatenated translation strings such as `tr("..." UTF8_HORIZONTAL_ELLIPSIS)` with complete UTF-8 literals inside `tr()`. Qt's translation extraction operates on the complete source string; macros concatenated outside the literal are not reliably represented in translation catalogs. A source tree that permits UTF-8 should keep translatable punctuation inside the translatable literal.

**!436 / !417 Qt scene and palette lifecycle** — Gerald Combs handles `ApplicationPaletteChange` by rebuilding packet-diagram scene state that depends on palette colors, and separately distinguishes per-packet `scene()->clear()` from a full scene reset when changing captures because QGraphicsScene retains rectangle/scroll state. UI reset granularity must match the lifetime of the state being invalidated.

**Guy Harris's !435 / !437 string-decoding APIs** — !435 adds explicit encodings for packed versus unpacked 3GPP TS 23.038 data and ETSI TS 102 221 Annex A strings, then migrates dissectors onto the common charset/tvbuff APIs. Names encode the representation distinction instead of leaving callers to guess which packing convention applies. !437 cleans an impossible duplicate return in the shared decoder. Centralize common wire encodings and name APIs for their actual representation.

**!432 / !420 / !419 checker-driven filter-name repairs** — Martin Mathieson added `check_typed_item_calls.py --consecutive` to flag adjacent fields with identical filter strings but different labels, then used it to find many genuine copy/paste filter-abbreviation defects. The checker deliberately reports suspicious cases; !448 demonstrates why not every warning should be “fixed” by forcing fields together. Tool findings are review signals, not a replacement for semantic comparison.

**!422 capture compression submission/design** — the merged gzip ring-buffer feature adds a CLI option and GUI control only where ring-buffer output exists. Ronnie Sahlberg required the incremental “fix the previous commit” history to be squashed into a coherent logical commit and corrected coding style; Gerald Combs pointed out `git commit --amend` as the normal way to refine an existing change. Feature UI/CLI enablement should follow the real applicability of the underlying mode, and review history should present the logical change rather than every local repair step.

**!416 QUIC streaming reassembly** — Peter Wu challenged an incomplete fix and pointed to TCP's corresponding state transition. The accepted revision avoids reusing the previous multisegment PDU once that PDU is fully assembled and the current sequence starts beyond its end, while also clearing completion state if a subdissector later requests more bytes. Reassembly state may be inherited only while the current bytes still belong to the same unresolved PDU; completion must be reversible when a downstream parser proves the aggregate was not actually complete.

**!411 USBLL transaction state** — the merged change introduces explicit transaction states rather than repeatedly inferring protocol phase by inspecting several prior packets. This makes invalid PID-sequence detection and future USB 2.0 reassembly more direct. Persistent protocol state should model the protocol's actual state machine when repeated backward inspection becomes the de facto state representation.

**Closed !409 HTTP/3/nghttp3** — the draft did not merge, but Peter Wu and Pascal Quantin's dependency discussion is useful lower-weight guidance: avoid vendoring a third-party library merely because some distributions do not package it yet; an optional dependency can be preferable, especially when bundling creates distribution-policy and static-analysis noise. Peter also requested robust shell quoting (`read -r`, quoted path variables). Because the MR closed, no proposed HTTP/3 architecture here is treated as accepted precedent.
