# Durable convention synthesis from MRs !559-!608

1. **Protocol-tree absence must not suppress semantic work.** First-pass parsing, validation, transaction correlation, state transitions, and other behavior needed by later passes must run even when `tree == NULL`. !564 is merged positive evidence; closed !562 supplies direct Pascal Quantin/Anders Broman negative review at the core API layer.
2. **Heuristic probe length comes from mandatory framing plus recognition needs, not maximum field width.** After proving the minimum packet structure, cap variable-identifier reads to captured bytes and require only the identity material that the heuristic actually needs. !571 provides merged QUIC evidence with Peter Wu review.
3. **Keep machine error identity and human diagnostic context separate but coupled.** A coarse error code can travel with an owned detail string that names the violated invariant. Initialize, propagate, display, and free both according to one API contract. Guy Harris's !579/!580 is authoritative Wiretap precedent.
4. **Centralize registered-field display semantics.** UI consumers should reuse libwireshark's field-rendering path rather than reproducing type/base/string rules independently. Gerald Combs's merged !601 provides the positive architecture; Guy Harris's closed-!585 review clarifies semantic string/display-value behavior.
5. **Use `ENC_TIME_*` field decoding where the wire representation matches it.** !565/!566 show that generic protocol-tree item decoding is preferable to manual integer-to-`nstime_t` reconstruction when no custom transform is needed.
6. **Generated grammar types can still require protocol-specific semantic validation.** !606 shows that a general ASN.1 `OCTET STRING` needs an explicit eight-byte check before treating it as a fixed-width gmIdentity/EUI-64.
7. **Treat ABI symbol manifests as release metadata.** !589 corroborates that a public symbol's version is the first release that actually ships it.
8. **Measure the systemic cost of widened global capacities.** !582 demonstrates reviewer expectation that a large increase in an allocation-related constant be accompanied by realistic memory-impact testing.
