# Durable Wireshark conventions from !6811-!6860

Corpus commit: `ddcaa22b51c68f594e425a23388c3a2086813054`.

## Sort the representation the user is viewing

Merged !6859, authored by Guy Harris, sorts name-resolved address columns by their resolved display strings rather than underlying binary addresses. Merged !6855 independently restricts packet-list sorting to the filtered visible set. A view-level sort should follow the active view's visible population and semantic representation, not hidden source rows or an undisplayed raw key.

## Snapshot mutable conversation state at packet boundaries for redissection

Merged !6852 stores evolving AT session state in conversation data but persists the state entering each packet so later redissection does not use knowledge learned from future packets. If parsing both consumes and advances conversation state, keep enough pre-packet state/history to make redissection independent of navigation order.

## Preserve source provenance when packaging outside a Git checkout

Merged !6831 and !6846 use commit IDs embedded by `git archive` to decide whether a source tarball matches the requested revision and to support RPM builds from extracted release sources. Packaging logic must not assume `.git` exists; provenance needed for version/reproducibility decisions should survive archive extraction and be verified before reusing an artifact.

## Narrow analyzer suppressions are acceptable for intentional special syntax

In !6846 John Thacker explains that ShellCheck SC2016 is a false positive: the single-quoted `$Format:%H$` must remain unexpanded by the shell so `git archive` can substitute it. When a static analyzer cannot model deliberate tool-specific syntax, use a local documented suppression rather than rewriting correct semantics or disabling the check globally.

## New features belong on master; fixes can then be backported

In merged !6838 Alexis La Goutte explicitly asks the contributor to move EAP feature work to master because release-3.6 receives fixes rather than new feature intake. The MR also supplies representative encrypted captures/keys; Windows CI catches a portability error and OSS-Fuzz later finds a memory-lifetime regression corrected by !6864. Feature development, sample-based validation, cross-platform CI, fuzzing, and subsequent focused fixes are complementary parts of the submission lifecycle.

## Prefer `pinfo->pool` for packet-lifetime dissector allocations

In merged !6825 Alexis La Goutte states that direct packet-scope use is being deprecated and asks the contributor to use `pinfo->pool`. This corroborates the notebook's existing allocator guidance: express packet-lifetime ownership through the packet's allocator and let scope teardown manage it. The same review also requires a representative capture; the contributor supplies decryption keys with the encrypted Wi-SUN sample.

## Run compile-context-sensitive analyzers only where build context exists

Merged !6829 changes `validate-clang-check.sh` to skip changed files that have no rule in `compile_commands.json` or `build.ninja`, since missing build rules commonly imply missing include/compile context. A source analyzer that depends on compiler invocation context should not pretend to validate files for which that context is unavailable.

## Optional terminators must not replace bounded-container parsing

Merged !6824 stops treating absence of an optional LLDP EndOfLLDPDU TLV as malformed and parses TLVs while the captured TVB still contains data. When a format permits EOF/container-end to terminate a repeated structure, parser progress should be bounded by the enclosing captured region rather than requiring a sentinel that the specification makes optional.

## Shared generated configuration should use the active product namespace

In merged !6821 Guy Harris catches a Logwolf configuration resource claiming it was generated by Wireshark. Merged follow-up !6842 introduces `get_configuration_namespace()` and emits the actual application namespace in generated files. Shared configuration code should not hard-code one frontend/product identity in user-visible provenance text.

## Clear prior-epoch state before processing the boundary message of a new epoch

Merged !6813 resets TLS/DTLS decryption/session state before the second ClientHello/ServerHello is added to the EMS handshake hash. Resetting later allowed stale master-secret state to suppress the first message of the renegotiated epoch. At an explicit handshake/rekey/session boundary, invalidate old derived state before any update for the boundary message.

## Typed-item checker output is useful pre-submit evidence but remains warning-oriented

Merged !6858 fixes duplicate/mistyped 802.11 filter abbreviations found by `tools/check_typed_item_calls.py`. Alexis La Goutte asks about CI coverage; Martin Mathieson notes the checker is already present and discusses adding then-current warning-only flags. Current repository tooling remains authoritative, and checker findings still require semantic review rather than mechanical application.
